# 调试模式使用指南

## 概述

现在 `vosk_local.py` 和 `parse_en.py` 都支持详细的调试输出，可以看到从音频到JSON的完整处理过程。

## 调试模式详解

### 阶段1：音频采集

```
🎤 开始新的识别会话
============================================================
🧹 清空了 2 个旧音频块         ← 清理残留数据
🔄 识别器状态已重置             ← 重置Vosk内部状态
⏱️  等待语音输入（超时 3 秒）...
📥 开始接收音频数据...          ← 麦克风开始工作
```

**诊断信息：**
- 如果没有 `📥 开始接收音频数据...`：麦克风未连接或权限未授予
- 如果有旧音频块：说明队列清理机制工作正常

### 阶段2：实时识别

```
  💭 部分识别: 'for'             ← Vosk实时输出（你说话时）
  💭 部分识别: 'forward'
  💭 部分识别: 'forward five'
  💭 部分识别: 'forward five second'
```

**诊断信息：**
- 部分识别可以让你看到Vosk"听到"了什么
- 如果部分识别不准确，可能是：
  - 音量太低
  - 噪音干扰
  - 发音不清晰
  - Grammar模式限制（加 --no-grammar）

### 阶段3：识别完成

```
✅ Vosk 识别完成 (耗时 1.85s)
📊 接收了 4 个音频块 (~2.0秒音频)
📝 原始识别文本: 'forward five seconds'
```

**诊断信息：**
- **耗时**: 正常范围 0.5-3秒
- **音频块数量**: 每块0.5秒，数量=识别时长
- **原始文本**: 这是Vosk的直接输出，未经解析

### 阶段4：文本解析

```
🔍 开始解析文本...
  ├─ 输入文本: 'forward five seconds'
  ├─ 规范化后: 'forward five seconds'    ← 转小写、合并空格
  ├─ 提取速度: 无                         ← 检查"speed L2"等
  ├─ 识别为: 前进命令                     ← 命令类型检测
  ├─ 正则匹配到数字部分: 'five'          ← 正则表达式提取
  ├─ 数字解析结果: 5                      ← 单词转数字
  ├─ 最终时长: 5000ms                     ← 单位转换 + 边界检查
  └─ 输出: {'action': 'forward', ...}
```

**诊断信息：**
- **规范化**：确保大小写统一
- **正则匹配**：如果这里是空或错误，说明正则需要调整
- **数字解析**：如果返回None，说明_num()不支持这个数字词

### 阶段5：超时情况

```
⏰ 超时 (3秒)
⚠️  没有接收到任何音频数据
   可能原因：麦克风未连接或权限未授予
```

或：

```
⏰ 超时 (3秒)
   接收了 6 个音频块，但未识别到完整语音
   部分识别: ['for', 'forward']
   可能原因：音量太低、噪音太大、或未说话
```

## 常用调试命令

### 1. 基础调试（Grammar模式）

```bash
python3 vosk_local.py --debug
```

适用场景：测试Grammar列表中的命令

### 2. 完整调试（无Grammar）

```bash
python3 vosk_local.py --debug --no-grammar
```

适用场景：测试任意数字和单词

### 3. 调试+长超时

```bash
python3 vosk_local.py --debug --no-grammar --timeout 10
```

适用场景：说话较慢或复杂命令

### 4. 指定设备调试

```bash
# 先列出设备
python3 vosk_smoke.py --list-devices

# 使用指定设备
python3 vosk_local.py --debug --device 1
```

适用场景：多个麦克风时选择特定设备

## 调试技巧

### 技巧1：对比原始文本和解析结果

如果Vosk识别正确，但解析错误：
```
📝 原始识别文本: 'forward eleven seconds'  ← Vosk正确
  ├─ 正则匹配到数字部分: 'eleven'          ← 正则正确
  ├─ 数字解析结果: None                    ← 解析失败！
```

**解决方案**：在 `parse_en.py` 的 `_num()` 函数中添加 "eleven" 支持

### 技巧2：检查部分识别

如果没有最终结果，看部分识别：
```
  💭 部分识别: 'foro'                       ← 识别不准确
  💭 部分识别: 'forward'                    ← 逐渐修正
```

**解决方案**：改善音频质量或启用Grammar模式

### 技巧3：音频块数量判断问题

```
📊 接收了 0 个音频块                         ← 麦克风问题
📊 接收了 20 个音频块 (~10.0秒音频)        ← 说太久或没检测到结束
```

### 技巧4：组合数字调试

测试 "twenty three"：
```
  ├─ 正则匹配到数字部分: 'twenty three'
  ├─ 数字解析结果: 23                       ← 组合解析成功
```

如果解析失败：
```
  ├─ 正则匹配到数字部分: 'twenty'           ← 只匹配到一部分
  ├─ 数字解析结果: 20                       ← 丢失了"three"
```

**解决方案**：检查正则表达式的非贪婪匹配

## 性能分析

### 正常延迟

```
✅ Vosk 识别完成 (耗时 1.85s)
📊 接收了 4 个音频块
```

**计算**: 
- 音频时长 = 4块 × 0.5秒 = 2.0秒
- 处理延迟 = 1.85秒 - 部分音频时间 ≈ 0.5-1秒
- 总延迟约 0.5-1秒是正常的

### 异常延迟

```
✅ Vosk 识别完成 (耗时 5.23s)
📊 接收了 4 个音频块
```

**分析**:
- 音频只有2秒，但处理了5秒
- 可能原因：CPU占用高、模型加载慢

## 故障案例分析

### 案例1：识别不到数字

**症状：**
```
📝 原始识别文本: 'forward seconds'  ← 缺少"five"
  ├─ 未匹配到数字，使用默认值
  ├─ 最终时长: 2000ms                ← 使用默认2秒
```

**原因**：Grammar模式不包含"five"  
**解决**：`python3 vosk_local.py --debug --no-grammar`

### 案例2：一直超时

**症状：**
```
⏰ 超时 (3秒)
⚠️  没有接收到任何音频数据
```

**排查步骤：**
1. 检查设备：`python3 vosk_smoke.py --list-devices`
2. 检查权限：macOS系统设置 → 麦克风
3. 测试录音：见 DEBUG_GUIDE.md

### 案例3：识别错误

**症状：**
```
📝 原始识别文本: 'for word five seconds'  ← 错误！
```

**原因**：Vosk误识别  
**解决**：
1. 启用Grammar模式（提高准确率）
2. 改善音频质量
3. 清晰发音

## 编程接口

在自己的代码中使用调试模式：

```python
from vosk_local import recognize_once
from parse_en import to_structured

result = recognize_once(timeout_s=5, debug=True)

result = to_structured("forward five seconds", debug=True)
```
